# Gmail 초대 메일 연결

앱의 운영자가 초대를 등록하면 Google Apps Script의 MailApp으로 안내 메일을 보냅니다. 받은편지함을 읽거나 Gmail 비밀번호를 저장하지 않습니다. Google 발송 한도와 계정 권한에 따라 발송이 제한될 수 있습니다.

## 처음 연결

1. 운영자 Gmail 계정으로 Apps Script 프로젝트를 만들고 `Code.gs` 내용을 붙여넣습니다. `CLASSROOM_URL`은 실제 앱 주소로 고정합니다.
2. `initializeMailer`를 실행하고 메일 발송 권한과 계정 이메일 확인 권한을 승인합니다. 초기화는 메일을 보내지 않습니다. Google의 미확인 앱 안내는 사용자가 직접 검토합니다.
3. 초기화 로그의 발신 계정을 확인하고 생성된 secret을 Sites의 `INVITE_MAIL_SECRET` 비밀 환경변수에 보관합니다. 이 값은 소스·스크린샷·공유 문서에 넣지 않습니다. 연결 후 초기화 로그 창을 닫습니다.
4. 웹 앱으로 배포합니다. 실행 사용자는 운영자 자신, 액세스 대상은 모든 사용자입니다. 로그인 없는 웹훅이지만 HMAC 서명이 맞는 요청만 발송합니다. 웹훅에는 자료 열람 기능이 없습니다.
5. 배포의 `/exec` URL을 `INVITE_MAIL_URL` 비밀 환경변수에 넣고 새 앱 버전을 배포합니다. 기존 초대 교사 이메일로 실제 발송을 확인합니다.

관리 중인 Google 프로젝트는 `수업서랍 초대 메일`이며 프로젝트 ID는 `1LvvwS2ABC2pD6nuLXL_C4Hstp_silekcVqEoTC0oDuy2QgQNODWuSk6s`입니다. [프로젝트 편집기](https://script.google.com/home/projects/1LvvwS2ABC2pD6nuLXL_C4Hstp_silekcVqEoTC0oDuy2QgQNODWuSk6s/edit)에서 운영자 계정으로 관리합니다.

## 동작

- 운영자만 초대·재발송 API를 호출할 수 있습니다. 초대 실패와 메일 발송 실패는 분리합니다. 메일이 실패해도 등록된 교사의 접근 권한은 유지합니다.
- 같은 이메일을 다시 등록해도 발송 완료 건은 중복 전송하지 않습니다. `메일 다시 보내기`는 1분 후 가능합니다. 일반적인 발송 실패 후 재시도는 30초 후 가능합니다.
- 이메일과 요청 ID·시각만 서버에서 서명합니다. 웹훅은 서명, 5분 유효 시간, 단일 수신자, 고정 메일 문구·접속 주소를 확인합니다. 요청 ID는 Apps Script에도 기록해 통신 재시도에 의한 중복을 막습니다.
- 전송 후 응답이 끊기면 같은 요청 ID로 결과를 확인합니다. Gmail 전송 자체의 완료가 불확실한 경우에는 자동으로 새 메일을 보내지 않고 `발송 결과 확인 필요`로 표시합니다. 받은편지함 도착을 확인한 상태와 발송 완료는 구분합니다.
- 발송 상태·발송 시각은 앱의 동료 목록에 남습니다. 이 정보는 일반 동료에게 공개하지 않습니다.

## 검증

`node --test tests/invitation-mail.test.mjs`는 SQLite 메일 상태와 서명 검증·중복·전송 결과 유실을 포함한 7개 검증을 수행합니다. 실제 Gmail로 메일을 보내지 않는 테스트입니다. `node tests/api.integration.mjs`는 로컬 D1에서 권한·초대·공유 흐름을 검증합니다. 로컬 테스트에 실제 메일 연결 값을 넣지 않습니다.

신규 마이그레이션 `drizzle/0002_high_inhumans.sql`은 발송 상태 테이블만 추가합니다. 기존 자료·모음·메모는 수정하지 않습니다. 배포에서는 Sites가 미적용 마이그레이션을 적용합니다.
